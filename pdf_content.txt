Exercise 03: Smart Room 
Step 1: Wokwi Hardware Setup 
●​ Sensors & Components: 1x DHT22, 1x Photoresistor (LDR), 2x LEDs (e.g., Red and Blue), 2x Push Buttons (Switches), 2x Resistors (330Ω). 
 


--- Page 11 ---
 
●​ Microcontroller: ESP32. 
●​ Goal: Manually wire the ESP32 to read environmental data and allow the 2 switches to control the 2 LEDs locally. 
Wiring Instructions: 
1.​ DHT22 (Temperature & Humidity): 
○​ Connect VCC to ESP32 3V3. 
○​ Connect GND to ESP32 GND. 
○​ Connect SDA to ESP32 GPIO. 
2.​ Photoresistor (LDR): 
○​ Connect VCC to ESP32 3V3. 
○​ Connect GND to ESP32 GND. 
○​ Connect AO to ESP32 GPIO. 
3.​ LED 1 (Main Room Light) & Switch 1: 
○​ Connect LED 1 Anode (+) to ESP32 GPIO. Connect Cathode (-) to a resistor (220 Ohm), then to GND. 
○​ Connect one side of Switch 1 to ESP32 GPIO. Connect the other side to GND. (We will use internal pull-up resistors in the code). 
4.​ LED 2 (AC/Fan Indicator) & Switch 2: 
○​ Connect LED 2 Anode (+) to ESP32 GPIO. Connect Cathode (-) to a resistor (220 Ohm), then to GND. 
○​ Connect one side of Switch 2 to ESP32 GPIO. Connect the other side to GND.Step 2:

Background: ​
I am conducting an IoT class where students are building a "Smart Room" edge node simulated in Wokwi, connecting to the 
ThingsBoard cloud platform. The hardware consists of an ESP32 microcontroller, a DHT22 sensor (temperature/humidity), a 
photoresistor (LDR), 2 LEDs (representing a room light and an AC unit), and 2 physical push-button switches. The device acts 
as a dual-purpose node: it handles local manual control via the switches and communicates bidirectionally with ThingsBoard 
to send telemetry and receive remote commands. 
Role:​
Act as an Expert Embedded Systems Engineer and IoT Educator. Your code should follow the "Keep It Simple, Stupid" (KISS) 
principle—making the edge node act as a lightweight data bridge while remaining highly readable for students learning C++ 
and IoT concepts. 
Instructions: ​
 


--- Page 12 ---
 
Write the complete Arduino/C++ .ino sketch for this ESP32 project. 
1.​ Libraries: Use the PubSubClient library for all MQTT communication and the standard Adafruit Libraries. 
2.​ Hardware Pins: 
○​ DHT22 on <pin number>. 
○​ LDR on <pin number>. 
○​ LED 1 (Light) on <pin number>. 
○​ LED 2 (AC) on <pin number>. 
○​ Switch 1 on <pin number> (use INPUT_PULLUP). 
○​ Switch 2 on <pin number> (use INPUT_PULLUP). 
3.​ Local Logic: Implement physical switch polling. Pressing a switch should toggle its respective LED. Include basic 
software debounce logic. 
4.​ Telemetry: Read the sensors and current LED states. Construct a JSON string containing temperature, humidity, 
light_level, light_status, and ac_status. Publish this to the ThingsBoard topic v1/devices/me/telemetry every 5 seconds. 
5.​ Remote Control (RPC): Subscribe to the ThingsBoard RPC topic v1/devices/me/rpc/request/+. Implement the callback 
function to parse incoming commands for setLightState and setACState, toggling the physical LEDs based on the cloud 
payload. 
Expectations: 
●​ Do not use delay() for the 5-second telemetry loop; use non-blocking millis() timing so the physical switches remain 
instantly responsive. 
●​ Include robust reconnect() logic for both WiFi and the MQTT broker. 
●​ Use simple String concatenation or snprintf for the JSON payload—avoid complex JSON libraries to keep the code 
footprint small and educational. 
●​ Add clear, instructional comments explaining the purpose of the WiFi setup, MQTT reconnect loop, and the RPC 
callback function. 
Format:​
Provide the complete, ready-to-compile C++ code in a single markdown code block. Below the code, provide a brief 
markdown table summarizing the GPIO pin mapping for the students to use as a wiring reference.

Step 2: ThingsBoard Platform Setup 
 


--- Page 13 ---
 
●​ Goal: Create the digital twin for your Smart Room to receive telemetry and send remote control commands. 
Instructions: 
1.​ Log in to your ThingsBoard instance (https://eu.thingsboard.cloud/). 
2.​ Navigate to Entities -> Devices and click the "+" icon to add a new device. 
3.​ Name it Smart_Room_Node and click Add. 
4.​ Click on your newly created device, click Manage Credentials, and copy the Access Token. 
Step 3: Create a Dashboard 
1.​ Go to Dashboards on the left menu. 
2.​ Click the "+" icon and select Create new dashboard. 
3.​ Name it "Smart Room" and open it. 
4.​ Click the Add Widget. 
5.​ Click Add new widget and select Digital Gauges (or Analog Gauges). 
6.​ Click on a gauge style. 
7.​ In the setup window, set Target Device directly to your Smart_Room_Node. 
8.​ In the Data keys box, select temperature and click Add. 
9.​ Repeat this process for humidity. 
10.​Optional: Do this once more, but choose Charts -> Timeseries Line Chart and select light_level to see a graph of the room's brightness. 
Likewise add LED to show the on off status of the light bulb. And also add a widget and display if it’s day or night based on LDR readings.
